Why GAMs?

You’ve probably fit a linear model before. Maybe even a generalized linear model (GLM). But what happens when your response doesn’t follow a straight line—or any parametric form you can easily specify?

Enter Generalized Additive Models (GAMs). GAMs let you model non-linear relationships without committing to a specific functional form. Instead of assuming y = β₀ + β₁x, you fit y = f(x), where f() is a smooth function learned from the data.

Think of GAMs as the sweet spot between:

  • Linear models: Fast, interpretable, but rigid
  • Machine learning: Flexible, but often black-box and unstable

GAMs give you flexibility with interpretability—you can see and understand the smooth functions.

The Basic Idea

A GAM replaces linear predictors with smooth functions:

Linear Model: $$y_i = \beta_0 + \beta_1 x_i + \epsilon_i$$

GAM: $$y_i = \beta_0 + f(x_i) + \epsilon_i$$

where \(f()\) is a smooth function estimated from the data.

For multiple predictors: $$y_i = \beta_0 + f_1(x_{1i}) + f_2(x_{2i}) + ... + \epsilon_i$$

The magic is in how we estimate these smooth functions—typically using penalized regression splines.

# 1. Linear model (wrong!)
lm_fit <- lm(sales ~ temperature, data = ice_cream)

# 2. Polynomial (have to guess the degree)
poly_fit <- lm(sales ~ poly(temperature, 3), data = ice_cream)

gam_fit <- gam(sales ~ s(temperature), data = ice_cream)

# Create predictions
temp_seq <- seq(0, 35, length.out = 200)
predictions <- data.frame(
  temperature = temp_seq,
  Linear = predict(lm_fit, newdata = data.frame(temperature = temp_seq)),
  Polynomial = predict(poly_fit, newdata = data.frame(temperature = temp_seq)),
  GAM = predict(gam_fit, newdata = data.frame(temperature = temp_seq))
)

# Reshape for plotting
library(tidyr)
pred_long <- predictions %>%
  pivot_longer(-temperature, names_to = "Model", values_to = "Prediction")

# Plot
ggplot() +
  geom_point(data = ice_cream, aes(x = temperature, y = sales), 
             alpha = 0.3, color = "gray50") +
  geom_line(data = pred_long, 
            aes(x = temperature, y = Prediction, color = Model),
            linewidth = 1.2) +
  scale_color_manual(values = c("Linear" = "#E69F00", 
                                 "Polynomial" = "#009E73",
                                 "GAM" = "#0072B2")) +
  labs(
    title = "Comparing Approaches to Non-linear Relationships",
    x = "Temperature (°C)",
    y = "Sales (units)"
  ) +
  theme_minimal() +
  theme(legend.position = "bottom")

The GAM (blue) captures the curve without us having to specify its functional form. The linear model is clearly wrong, and the polynomial works but required us to guess the degree.

Key outputs:

  • EDF (Estimated Degrees of Freedom): How “wiggly” the smooth is. EDF ≈ 1 is nearly linear, higher values are more flexible
  • p-value: Is this smooth term significant?
  • R-squared: Proportion of variance explained

# Fit a GAM with specific basis dimension
gam_k5 <- gam(sales ~ s(temperature, k = 5), data = ice_cream)

preds <- data.frame(
  temperature = temp_seq,
  k5 = predict(gam_k5, newdata = data.frame(temperature = temp_seq)),
  k10 = predict(gam_k10, newdata = data.frame(temperature = temp_seq)),
  k20 = predict(gam_k20, newdata = data.frame(temperature = temp_seq))
) %>%
  pivot_longer(-temperature, names_to = "Basis_k", values_to = "Prediction")

ggplot() +
  geom_point(data = ice_cream, aes(x = temperature, y = sales), 
             alpha = 0.2, color = "gray50") +
  geom_line(data = preds, 
            aes(x = temperature, y = Prediction, color = Basis_k),
            linewidth = 1) +
  labs(
    title = "Effect of Basis Dimension (k)",
    subtitle = "Higher k allows more flexibility",
    x = "Temperature (°C)",
    y = "Sales (units)",
    color = "Basis size"
  ) +
  theme_minimal()

The k parameter controls the maximum wiggliness. But don’t worry—GAMs use penalization to prevent overfitting. A large k just gives the model room to be flexible if needed.

What to look for:

  4. k-index: Should be > 1 (if < 1, try increasing k)

set.seed(123)

# Simulate home range data
n <- 300
habitat_data <- data.frame(
  body_mass = exp(rnorm(n, 3, 0.5)),  # kg (log-normal)
  food_availability = runif(n, 0, 100),  # index
  population_density = runif(n, 0, 50)  # individuals/km²
)

# Home range size with complex relationships
habitat_data$home_range <- with(habitat_data,
  50 * log(body_mass) +  # Allometric scaling
  -0.3 * food_availability +  # More food = smaller range
  0.5 * sqrt(population_density) +  # Density-dependent
  -0.002 * food_availability^2 +  # Diminishing returns
  rnorm(n, 0, 20)
)

# Fit multi-predictor GAM
range_gam <- gam(home_range ~ s(body_mass) + s(food_availability) + 
                   s(population_density),
                 data = habitat_data)

summary(range_gam)

# Simulate data with interaction
set.seed(456)
interact_data <- data.frame(
  x1 = runif(200, 0, 10),
  x2 = runif(200, 0, 10)
)

# Response depends on interaction
interact_data$y <- with(interact_data,
  10 + 2 * x1 + 3 * x2 + 0.5 * x1 * x2 +  # Interaction
  sin(x1) * cos(x2) +  # Non-linear interaction
  rnorm(200, 0, 2)
)

# Fit interaction GAM using tensor product (te)
interact_gam <- gam(y ~ te(x1, x2), data = interact_data)

# Visualize the interaction surface
vis.gam(interact_gam, view = c("x1", "x2"), 
        theta = 45, phi = 30,
        color = "terrain",
        main = "Interaction Surface: y ~ te(x1, x2)")

Types of interactions in mgcv:

  • s(x1, x2): Isotropic smooth (assumes same scale for both)
  • te(x1, x2): Tensor product (different scales, more flexible)
  • ti(x1, x2): Tensor product interaction only (excludes main effects)

# Count data example (Poisson)
set.seed(789)
count_data <- data.frame(
  effort = seq(1, 50, length.out = 150)
)

# Expected counts increase non-linearly with effort
count_data$lambda <- exp(2 + 0.1 * count_data$effort - 
                         0.001 * count_data$effort^2)
count_data$counts <- rpois(150, count_data$lambda)

# Fit Poisson GAM
count_gam <- gam(counts ~ s(effort), 
                 data = count_data, 
                 family = poisson())

# Plot on response scale
plot_data <- data.frame(
  effort = seq(1, 50, length.out = 200)
)
plot_data$predicted <- predict(count_gam, 
                               newdata = plot_data, 
                               type = "response")

ggplot() +
  geom_point(data = count_data, aes(x = effort, y = counts), alpha = 0.5) +
  geom_line(data = plot_data, aes(x = effort, y = predicted), 
            color = "#0072B2", linewidth = 1.2) +
  labs(
    title = "Poisson GAM for Count Data",
    x = "Sampling Effort",
    y = "Species Count"
  ) +
  theme_minimal()

Common families:

  • gaussian(): Normal response (default)
  • poisson(): Count data
  • binomial(): Binary or proportion data
  • Gamma(): Positive continuous data
  • nb(): Negative binomial (overdispersed counts)
  • tw(): Tweedie (zero-inflated continuous)

set.seed(101)

# Time series with autocorrelation
n_years <- 100
time_data <- data.frame(
  year = 1:n_years
)

# Population with trend + cycles + autocorrelation
time_data$population <- 100 + 
  0.5 * time_data$year +  # Linear trend
  20 * sin(2 * pi * time_data$year / 10) +  # 10-year cycle
  arima.sim(list(ar = 0.7), n = n_years)  # AR(1) noise

# Fit GAM (incorrectly assuming independence)
time_gam_naive <- gam(population ~ s(year), data = time_data)

# Fit GAM with AR(1) correlation structure
time_gam_ar <- gamm(population ~ s(year), 
                    correlation = corAR1(form = ~ year),
                    data = time_data)

# Compare
summary(time_gam_ar$gam)

# Multi-site study
sites <- paste0("Site", 1:10)
site_data <- expand.grid(
  site = sites,
  temperature = seq(0, 30, length.out = 20)
)

# Random intercept for each site
site_effects <- rnorm(10, 0, 30)
names(site_effects) <- sites

site_data$abundance <- with(site_data,
  100 +  # Global intercept
  site_effects[as.character(site)] +  # Random intercept
  5 * temperature - 0.1 * temperature^2 +  # Fixed effect
  rnorm(nrow(site_data), 0, 10)
)

# Fit GAM with random effect
site_gam <- gam(abundance ~ s(temperature) + s(site, bs = "re"),
                data = site_data)

  precipitation = runif(n_obs, 200, 2000),
  temperature = runif(n_obs, -5, 25)
)

# Probability of presence depends on environmental niche
species_data$prob <- with(species_data,
  plogis(  # Convert to 0-1 probability
    -5 +  # Low baseline probability
    0.003 * elevation - 0.000001 * elevation^2 +  # Unimodal
    0.005 * precipitation - 0.000003 * precipitation^2 +  # Unimodal
    0.2 * temperature - 0.01 * temperature^2  # Unimodal
  )
)

species_data$presence <- rbinom(n_obs, 1, species_data$prob)

# Fit species distribution model (SDM)
sdm <- gam(presence ~ s(elevation) + s(precipitation) + s(temperature),
           data = species_data,
           family = binomial(),
           method = "REML")  # REML is more stable for binomial

summary(sdm)

When to Use GAMs

Use GAMs when:

  • Relationships are clearly non-linear
  • You want interpretable smooth functions
  • You have enough data (hundreds of observations minimum)
  • Predictors are continuous
  • You need to model interactions

Don’t use GAMs when:

  • Linear relationships work fine (simpler is better!)
  • Sample size is very small (< 50-100)
  • You need truly causal inference (consider DAGs first)
  • Prediction is more important than interpretation (try ML)

Summary

GAMs are powerful tools for ecological data analysis:

✓ Flexible: Model complex non-linear relationships
✓ Interpretable: Visualize and understand smooth functions
✓ Automatic: Penalization prevents overfitting
✓ Extensible: Handle multiple distributions, random effects, spatial/temporal correlation
✓ Well-supported: mgcv is mature, fast, and well-documented

Key functions:

  • gam(): Main workhorse
  • gamm(): For mixed models and correlation structures
  • gam.check(): Diagnostic plots
  • summary(): Model results
  • plot(): Visualize smooths
  • predict(): Make predictions

Further Reading

  • The GAM Bible: Wood, S.N. (2017). Generalized Additive Models: An Introduction with R (2nd ed.)
  • mgcv documentation: ?gam and package vignettes
  • gratia package: Modern ggplot2-based GAM visualization
  • Noam Ross’s GAM course: Free online resource
